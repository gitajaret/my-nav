第四步：兜底教程

让别的 AI 手把手教你配，附求助模板和安全红线

配置卡住了、报错看不懂、文档太乱？最省事的兜底办法—— 打开任意一个能用的 AI （DeepSeek 官网、豆包、Kimi、ChatGPT 都行），

把下面这套「求助模板」发给它，它会一步一步带你点。比翻帖子快，也比自己瞎试省时间。

第一步：把「配置求助模板」整段发给 AI

先填好你的软件名和版本，其余照抄即可：

text
我在配置一个 AI 客户端软件，要接入一个「OpenAI 兼容」的中转接口。
接口信息：
- Base URL：https://api.juheai.shop/v1 （如果这是 Claude 系软件，改为 https://api.juheai.shop，不带 /v1）
- API Key：sk-****（我已有，完整密钥不便提供）
- 可用模型：deepseek-v4-flash、deepseek-v4-pro、gemini-3.1-pro、claude-sonnet-5-5
我用的软件是：【写软件名和版本，例如「SillyTavern 最新版」】
这个软件是图形界面，还是命令行？【按实际情况写】

请一步一步告诉我：在软件的哪个菜单、点哪个按钮、每个字段填什么。
假设我是完全没用过的小白，每一步都要具体，并告诉我做完之后怎么验证是否成功。

第二步：把报错原文喂回去

如果按它说的配完还是报错，别自己猜——把 报错原文 再发给它，并补上这句：

text
我按你说的配置后，软件报错如下：
【粘贴报错原文，或把报错截图转成文字】
我之前填的 Base URL 是 https://api.juheai.shop/v1，软件是【软件名 + 版本】。
请分析最可能的原因，并给我一步步的修复步骤；如果涉及模型名，请只使用我上一条列出的可用模型。

第三步：拿到步骤后，先核对这三件事再用

要核对为什么
字段 / 开关名是否与当前版本一致AI 可能给出过时写法。例如 Codex 的 wire_api = "chat" 早已废弃，现在只能用 "responses"；对不上就以软件官方最新文档为准。
地址是不是本站确认填的是 api.juheai.shop；该带 /v1 的带、不该带的不带（Claude 系不带）。
模型名是不是真存在AI 可能编造模型名。模型名一律以「模型广场」里展示的为准，逐字照抄。

让 AI 帮忙的三条安全红线：

① 密钥务必打码 （ sk-abc****xyz ），别把完整密钥发给任何 AI 或贴到公开网站。

② AI 可能给出 过时的字段写法 ，拿不准就让它「以官方最新文档为准」再确认一遍。

③ 让 AI 生成的配置文件（如 Codex 的 config.toml 、Claude Code 的 settings.json ）， 保存前先看一眼 ，确认里面没有混进别人的地址或密钥。

进阶：让 AI 帮你逐行核对配置文件

如果你已经有一份配置文件（ config.toml / settings.json / .env 等），可以整份贴给它，让它在不泄露密钥的前提下逐行解释、指出哪里填错：

text
下面是我的配置文件（密钥已打码）。请逐行说明每项作用，并指出接入中转接口时哪里填错、应改成什么：
【粘贴配置文件内容，密钥打码】

还搞不定？ 按 求助三件套 把「终端最后几行 + 你做到第几步 + 报错原文」发给客服，基本一看就知道问题在哪。

还搞不定？找客服

按「求助三件套」把下面三样发给我们，基本一看就知道问题在哪：

#提供什么
1终端里最后 5～10 行文字（可截图，注意别拍到密钥）
2你做到第几步了
3报错的原文或截图

密钥属于隐私，发送前可以先给后几位打码。
