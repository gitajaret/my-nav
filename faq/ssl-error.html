SSL / 证书错误（x509）

报 SSL certificate problem、TLS handshake 时看这篇

报错长这样

text
SSL certificate problem
x509: certificate signed by unknown authority
TLS handshake timeout
certificate verify failed
unable to get local issuer certificate
SSL_ERROR_BAD_CERT_DOMAIN

这是什么意思

你的电脑在跟我们建立加密连接（HTTPS）时，认为对方的证书不可信。

打个比方：你收到一封信，信封上盖的章看起来不对劲，邮局不敢递给你。

正常情况下，网站证书由权威机构签发，你的系统认识它。出现这个报错，通常是中间有人在拦截并解密你的流量。

谁在拦截你的流量

按可能性从高到低：

拦截者怎么产生占比
代理软件部分代理做 MITM（中间人解密）最高
杀毒软件「HTTPS 扫描」「网页防护」功能高
公司网关上网行为管理设备中（办公网络）
抓包工具Fiddler、Charles 等低

第一步：关掉杀毒软件的 HTTPS 扫描

这是国产杀毒软件的高频问题。在设置里找这几项，全部关掉：

找什么关键词说明
HTTPS 扫描 / SSL 扫描会解密所有加密流量
网页防护 / 网络防护同上
流量监控 / 上网保护同上
证书管理 / 根证书会往系统里装自己的证书

常见位置：

text
360 安全卫士 → 设置 → 安全防护中心 → 网络防护
火绒 → 设置 → 网络防护 → HTTPS 扫描
腾讯电脑管家 → 设置 → 实时防护 → 网页防护
卡巴斯基 → 设置 → 附加 → 网络 → 加密连接扫描

第二步：关掉代理软件

完全退出（不是暂停）。或者把我们的域名加入代理的例外列表。

处理方式做法
直接退出托盘图标 → 右键 → 退出
加例外规则里加 DOMAIN-SUFFIX,juheai.shop,DIRECT

第三步：确认地址没写错

证书是按域名签发的。域名写错，证书就对不上：

检查项正确写法错误写法
协议https://http://（不走加密）
域名api.juheai.shopapi.juheai.shop （带空格）
结尾不加 /v1/v1/ 或 //

正确：

text
https://api.juheai.shop

第四步：更新系统证书

证书库太旧也会报错。

系统怎么更新
Windows设置 → 更新和安全 → Windows 更新 → 检查更新
macOS系统设置 → 通用 → 软件更新
Android设置 → 系统 → 系统更新

第五步：清理可疑的根证书

如果之前装过抓包工具或某些软件，系统里可能残留了它们的根证书。

Windows 检查方法：

text
1. 按 Win+R，输入 certmgr.msc 回车
2. 左侧展开「受信任的根证书颁发机构」→「证书」
3. 往下翻，看有没有可疑的名字
   （如 Fiddler、Charles、某代理软件名、某公司名）
4. 有的话，右键 → 删除

注意：不确定的证书不要随便删，删错了可能影响其他网站。只删你明确认识的、来自代理或抓包工具的。

公司电脑特别说明

如果这是公司配的电脑，很可能装了上网行为管理或证书监控软件。

这种情况你自己改不了，因为：

障碍说明
权限不足装/删根证书需要管理员权限
公司策略IT 部门强制安装，不允许移除
安全合规移除可能违反公司规定

建议做法

text
1. 换一台个人电脑测试
2. 或用手机（用手机流量，不连公司 Wi-Fi）测试
3. 确认账号本身正常
4. 确实需要公司电脑用 → 找 IT 部门沟通

判断是不是你这边的问题

现象判断
手机上能用，电脑不能电脑的杀软或代理问题
手机流量能用，手机 Wi-Fi 不能你的 Wi-Fi 或路由器问题
所有设备都不能联系我们
只有某些网站报错该网站证书问题
