回答到一半断了（流式中断）

报错长这样

text
OpenAI stream disconnected before completion
stream ended before a terminal event
Upstream response stream was interrupted
Upstream HTTP/2 stream failed
连接中断
回答到一半停了

这是什么意思

AI 正在一个字一个字地输出回答（这叫做「流式输出」），输出到一半突然断了。

注意：这时候 HTTP 状态码可能是 200（成功），但内容没给完。所以客户端有时显示「成功」但实际是断的。

最常见的原因：网络不稳

流式输出需要保持一条长连接。如果中间网络抖了一下，连接就断了。

原因占比
开了梯子，线路不稳最高
本地网络抖动（Wi-Fi 不稳）次之
上游服务抖动可能
客户端超时设太短也可能

按这个顺序试（六步）

第一步：直接重发

多数情况重试就好，只是网络抖了一下。先重发一次试试。

第二步：关掉梯子

如果开了代理，关掉再试。代理线路的中断率明显更高。

第三步：总在同一处断 → 换个问法

如果每次都断在完全相同的位置：

现象说明
断在同一个词那段内容触发了过滤
断在同一个话题上游解析不了那个话题
断在固定长度可能是 token 上限

换个说法重新问，通常就能过。

第四步：超长回答分段要

如果回答本来就很长（几千字）：

text
❌ 不要：一次让它写完整篇一万字

✅ 应该：先写第一部分，说「继续」写第二部分，依次往下

一次生成特别长的内容，中途断掉的概率很高。

第五步：关掉流式输出

有些客户端在流式模式下有 bug：

客户端怎么关
Cherry Studio设置 → 关闭「流式输出」「Stream」
ChatBox设置 → 高级 → 关闭 Stream
NextChat设置 → 关闭 Stream
Cursor设置 → 关闭 Stream

关掉后变成「等全部生成完再一起返回」，慢一点但不容易断。

第六步：调长客户端超时

设置项建议值
请求超时至少 60 秒
复杂任务300 秒

设太短的话，AI 还在回答，客户端就主动放弃了。

状态显示成功但没内容

如果客户端显示「成功」但什么都没收到：

text
1. 关掉流式输出再试
2. 重启客户端
3. 换一个客户端测试（排除客户端 bug）
4. 都试过还不行 → 联系我们

判断是谁的问题

现象判断怎么办
重发就好了网络抖动正常，不用管
换客户端也断上游或线路联系我们
只有这个对话断内容触发换问法
所有对话都断网络配置查代理和超时设置

四种报错的细微区别

报错含义
stream disconnected连接被断开
no terminal event流没正常结束（缺结束标记）
stream was interrupted流被打断
HTTP/2 stream failedHTTP/2 协议层出错（可尝试降级）
