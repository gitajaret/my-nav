回答到一半断了（流式中断）

报 stream disconnected、回答突然停止时看这篇

📑 本文目录

报错长这样这是什么意思最常见的原因：网络不稳按这个顺序试状态显示成功但没内容判断是谁的问题还是不行

报错长这样

text
OpenAI stream disconnected before completion
stream ended before a terminal event
Upstream response stream was interrupted
Upstream HTTP/2 stream failed
连接中断
回答到一半停了

这是什么意思

AI 正在一个字一个字地输出回答，输出到一半突然断了。

注意：这时候 HTTP 状态码可能是 200（成功），但内容没给完。

最常见的原因：网络不稳

流式输出需要保持一条长连接。如果中间网络抖了一下，连接就断了。

原因占比
开了梯子，线路不稳最高
本地网络抖动次之
上游服务抖动可能
客户端超时设太短也可能

按这个顺序试

第一步：直接重发

多数情况重试就好，只是网络抖了一下。先重发一次。

第二步：关掉梯子

如果开了代理，关掉再试。代理线路的中断率明显更高。

第三步：总在同一处断 → 换个问法

如果每次都断在完全相同的位置：

  • 说明是那段内容触发了问题
  • 可能触发了内容过滤
  • 也可能是上游解析不了那个话题

换个说法重新问，通常就能过。

第四步：超长回答分段要

如果回答本来就很长（几千字）：

  1. 让它先写第一部分
  2. 说「继续」写第二部分
  3. 别一次让它生成几万字

一次生成特别长的内容，中途断掉的概率很高。

第五步：关掉流式输出

有些客户端在流式模式下有 bug：

客户端怎么关
Cherry Studio设置 → 关闭「流式输出」「Stream」
ChatBox设置 → 高级 → 关闭 Stream
NextChat设置 → 关闭 Stream

关掉后变成「等全部生成完再一起返回」，虽然慢一点，但不容易断。

第六步：调长客户端超时

设置项建议值
请求超时至少 60 秒
复杂任务300 秒

设太短的话，AI 还在回答，客户端就主动放弃了。

状态显示成功但没内容

如果客户端显示「成功」但什么都没收到：

  1. 关掉流式输出再试
  2. 重启客户端
  3. 换一个客户端测试（排除客户端 bug）

判断是谁的问题

现象判断
重发就好了网络抖动，正常
换客户端也断上游或线路问题
只有这一个对话断内容触发的，换问法
所有对话都断网络或客户端配置问题

还是不行

  • 是否每次都断在同一处
  • 用的什么客户端
  • 是否开了代理
  • 大概什么时间开始出现的
