401 认证失败（密钥无效）

报 401 Unauthorized、invalid api key 时看这篇
🗓 2026-11-03⏱ 约 5 分钟📑 12 个小节
📑 本文目录
目录
报错长这样这是什么意思九成是这三个原因第一步：重新复制（最有效）第二步：检查首尾空格第三步：确认密钥还有效第四步：确认客户端填对了位置第五步：新建密钥测试密钥的完整格式其他少见原因检查清单还是不行

报错长这样

text
401 Unauthorized
invalid api key
incorrect api key provided
Authentication failed
No API key provided
密钥无效

这是什么意思

服务器说：我不认识你这个密钥。

就像你拿错了门禁卡，刷卡机不认识，门打不开。

九成是这三个原因

原因占比
复制密钥时带了空格或换行最常见
密钥填错位置第二
密钥被删除或停用了第三

第一步：重新复制（最有效）

不要手动输入，也不要用鼠标拖选。

text
1. 登录后台 https://api.juheai.shop
2. 进入「API 密钥」页面
3. 找到你的密钥，点「复制」按钮
4. 到客户端里，全选清空原来的内容
5. 粘贴

为什么必须用复制按钮？

手动拖选容易带上首尾的空格、换行，或者漏掉最后一个字符。

第二步：检查首尾空格

粘完之后，把光标放到密钥最前面和最后面，看有没有多余空格。

正确的密钥格式：

text
sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

检查四点：

检查正确
开头sk-
中间没有空格
末尾没有换行
长度完整，没截断

第三步：确认密钥还有效

在后台「API 密钥」页面看状态：

状态说明处理
正常 / 启用可以用—
已禁用被停用了启用或新建
已过期到期了新建
不存在被删了新建

第四步：确认客户端填对了位置

不同客户端叫法不同，但本质都是「API Key」：

客户端填在哪
Cherry Studio设置 → 模型服务 → API 密钥
ChatBox设置 → API Key
NextChat设置 → 接口 → API Key
CursorSettings → Models → OpenAI API Key
Claude Code环境变量 ANTHROPIC_AUTH_TOKEN

常见错误：有些客户端有两个输入框，一个是「API 地址」，一个是「API 密钥」。别填反了。

第五步：新建密钥测试

如果上面都试了还是 401：

text
1. 后台新建一把密钥
2. 用新密钥测试
3. 新密钥能用 → 说明旧密钥确实失效了
4. 新密钥也不能用 → 联系我们

密钥的完整格式

如果你的客户端能看完整请求，检查 Authorization 头：

text
Authorization: Bearer sk-xxxxxxxx

注意：

正确错误
Bearer sk-xxx（一个空格）Bearer: sk-xxx（多了冒号）
Bearer sk-xxxbearer sk-xxx（大小写）

大多数客户端会自动处理，有些需要手动填。

其他少见原因

原因说明
密钥填到了别的字段有些客户端有多个 key 字段
用了别人的密钥抄的时候抄错了
密钥被管理员重置联系我们确认
环境变量没生效改完要重启终端

检查清单

text
□ 是用复制按钮复制的吗？
□ 粘贴前清空了旧内容吗？
□ 首尾没有空格？
□ 开头是 sk- 吗？
□ 后台显示状态正常吗？
□ 填在「API 密钥」而不是「API 地址」栏了吗？
□ 新建密钥测试过了吗？

还是不行

联系我们时提供：

#信息
1报错完整文字
2客户端名称和版本
3密钥的前 8 位（完整密钥不要发）
4是否新建过密钥测试
