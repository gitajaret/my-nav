401 认证失败（密钥无效）

报 401 Unauthorized、invalid api key 时看这篇

📑 本文目录

报错长这样这是什么意思九成是这三个原因第一步：重新复制密钥第二步：检查首尾有没有空格第三步：确认密钥还有效第四步：确认客户端填对了第五步：新建一个密钥测试完整的密钥格式检查还是不行

报错长这样

text
401 Unauthorized
invalid api key
incorrect api key provided
Authentication failed
No API key provided
密钥无效

这是什么意思

服务器说：我不认识你这个密钥。

就像你拿错了门禁卡，刷卡机不认识，门打不开。

九成是这三个原因

原因占比
复制密钥时带了空格或换行最常见
密钥填错位置（填到了别的地方）第二
密钥被删除或停用了第三

第一步：重新复制密钥

这是最有效的办法，不要手动输入。

  1. 登录后台 https://api.juheai.shop
  2. 进入「密钥」页面
  3. 找到你的密钥，点复制按钮（不要手动选文字）
  4. 到客户端里，全选清空原来的内容
  5. 粘贴

重点：复制按钮复制的才是干净的。手动拖选容易带上首尾的空格、换行、或者漏掉最后一个字符。

第二步：检查首尾有没有空格

粘完之后，把光标放到密钥最前面和最后面，看有没有多余的空格。

密钥应该长这样：

text
sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
  • sk- 开头
  • 中间没有空格
  • 末尾没有换行

第三步：确认密钥还有效

在后台「密钥」页面看：

状态说明
正常可以用
已禁用被停用了，需要启用或新建
已过期需要新建
不存在被删了，需要新建

第四步：确认客户端填对了

不同客户端叫法不一样，但本质都是填 API Key：

客户端填在哪
Cherry Studio设置 → 模型服务 → API 密钥
ChatBox设置 → API Key
NextChat设置 → 接口 → API Key
CursorSettings → Models → OpenAI API Key
Claude Code环境变量 ANTHROPIC_AUTH_TOKEN

注意：有些客户端有两个输入框，一个是「API 地址」，一个是「API 密钥」。别填反了。

第五步：新建一个密钥测试

如果还是 401：

  1. 在后台新建一个密钥
  2. 用新密钥测试
  3. 新密钥能用 → 说明旧密钥确实失效了
  4. 新密钥也不能用 → 联系我们

完整的密钥格式检查

如果你的客户端支持看完整请求，检查 Authorization 头：

text
Authorization: Bearer sk-xxxxxxxx
  • Bearer 后面有一个空格
  • 然后是密钥
  • 不要写成 Bearer: sk-xxx（多了冒号）

大多数客户端会自动处理，但有些需要你手动填。

还是不行

联系我们时提供：

  • 报错完整文字
  • 客户端名称
  • 密钥的前 8 位（完整密钥不要发，安全起见）
  • 是否新建过密钥测试
