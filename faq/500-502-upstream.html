500 / 502 上游服务错误

报错长这样

text
500 Internal Server Error
502 Bad Gateway
convert_request_failed
upstream error
bad_response_status_code
上游服务异常

这是什么意思

模型提供方那边出问题了。

用快递打比方：

环节对应
你客户端
快递站我们的网关
发货仓上游模型服务商

500 / 502 就是「发货仓」出问题了，不是你填错，也不是快递站的问题。

状态码含义
500上游服务器内部错误（它自己崩了）
502上游返回了错误的响应，网关无法处理

第一步：等 1 分钟再试

上游临时故障，大部分几分钟内自动恢复。

先等一下再试一次，很可能就好了。

第二步：判断是哪种情况

按下面的顺序试，能快速定位：

text
1. 换个模型试 → 别的能用？说明是这个模型的问题
2. 过 5 分钟再试 → 好了？说明是上游临时故障
3. 换个时间试（比如晚上再试）→ 好了？说明是高峰期拥堵
3. 以上都不行 → 联系我们

情况一：只有某个模型报错

说明那个模型的线路有问题。

做法说明
换同类模型都是 GPT 系列换另一个版本
联系我们告诉我们是哪个模型，我们换线路

情况二：所有模型都报 502

可能是你密钥所属分组对应的上游全挂了。

这种情况联系我们，会给你切到备用线路。

情况三：只有你的请求报错

可能是你的请求里有特殊内容：

可能原因怎么试
请求体太大（塞了长文件）拆小一点再发
特殊字符把那部分删掉试试
单次输出太长让它分段写

特别提醒：convert_request_failed

如果报错里出现这个词，这是协议不匹配，不是上游故障。

意思是：你的客户端说的是 A 语言，但那个分组说的是 B 语言，双方对不上。

你在用什么需要什么分组
Claude Code、Claude 客户端支持 Anthropic 协议的分组
ChatGPT、Cherry Studio、Cursor、ChatBox支持 OpenAI 协议的分组

怎么判断自己该用哪种

text
跑 Claude 模型 → 用 Anthropic 协议的分组
跑 GPT / DeepSeek / Gemini 模型 → 用 OpenAI 协议的分组
不确定 → 问客服，或看模型广场的分组说明

解决办法：回控制台，用协议对得上的分组重新建一把密钥。

怎么确认真的是上游问题

三个快速验证方法：

方法怎么做说明
换模型用另一个模型发同样的内容能通 = 是这个模型的问题
换时间过 10 分钟再试好了 = 上游临时故障
看状态问一下同事/群里的人大家都这样 = 上游故障

500/502 和 504 的区别

这三个码容易混，对比一下：

状态码含义典型原因你该做什么
500上游内部错误上游代码崩了等，或换模型
502上游响应异常上游返回了错的数据等，或换模型
504网关超时上游处理太慢，等不及了简化问题，或分段

共同点：都不是你填错了，都值得先等一下再试。

需要提供的信息

联系客服时给这几样，能快速定位：

text
□ 完整报错（含状态码，最好截图）
□ 用的哪个模型
□ 出现的确切时间
□ 换模型试过吗？结果如何
□ 出现频率：每次都这样 还是 偶尔
